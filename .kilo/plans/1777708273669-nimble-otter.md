# Adaptation Plan: ARC Models to CIFAR Dataset

## Overview
This plan outlines the steps to adapt the existing ARC-focused Vision Transformer and LoopViT models to work with the CIFAR-10/CIFAR-100 datasets. The current models are designed for ARC tasks (grid-based reasoning with discrete color predictions), while CIFAR requires standard image classification.

## Environment Setup
- **Local Development**: Python 3.12 with uv environment management
- **Execution Target**: Kaggle servers via command line or notebook
- **Dependency Management**: uv for local environment, requirements.txt for Kaggle
- **Code Portability**: Ensure all paths and imports are environment-agnostic

### Environment Considerations
- Develop and test locally using Python 3.12 with uv
- Ensure compatibility with Kaggle's environment (typically Python 3.9+)
- Create requirements.txt that captures all dependencies for Kaggle execution
- Test notebook compatibility if planning to run in Kaggle notebooks

## Key Differences to Address
1. **Input format**: ARC uses small grids (typically 30x30) with discrete color values; CIFAR uses 32x32 RGB images
2. **Output format**: ARC predicts per-pixel color labels; CIFAR requires image-level class predictions
3. **Task structure**: ARC uses task tokens for multi-task learning; CIFAR is typically single-task classification
4. **Scale**: CIFAR may benefit from different architectural choices than ARC's reasoning-focused design

### Kaggle-Specific Considerations
- **Dataset Access**: Use Kaggle's built-in CIFAR-10/CIFAR-100 datasets or download via API
- **Compute Resources**: Leverage Kaggle's GPUs/TPUs for faster training
- **Execution Mode**: Plan for both script execution (.py) and notebook (.ipynb) usage
- **Output Handling**: Save models, logs, and results to Kaggle's working directory

## Adaptation Strategy
We will primarily adapt the `ARC_ViT.py` and `ARC_LoopViT.py` models, modifying them for CIFAR classification while preserving useful architectural innovations.

## Detailed Implementation Plan

### Environment Considerations
- Develop and test locally using Python 3.12 with uv
- Ensure compatibility with Kaggle's environment (typically Python 3.9+)
- Create requirements.txt that captures all dependencies for Kaggle execution
- Test notebook compatibility if planning to run in Kaggle notebooks

### Phase 1: Core Model Modifications

#### 1.1 Modify Input Processing
- Replace color embedding with standard RGB pixel normalization
- Adjust patch embedding to handle 3-channel CIFAR images
- Remove or modify task token embeddings (set num_task_tokens=0 for single-task)

#### 1.2 Modify Output Head
- Change from per-pixel color prediction to global image classification
- Replace output projection: `num_colors * patch_area` → `num_classes` (10 or 100)
- Add global pooling (CLS token or mean pooling) before final classification

#### 1.3 Adjust Architecture Parameters
- Consider increasing model capacity for CIFAR:
  - Embedding dimension: 256 → 384 or 512
  - Depth: 6 → 8-12 layers (especially for ViT)
  - For LoopViT: Evaluate optimal loop_core_depth vs unique layers
- Adjust patch size: Current default=2 may be too small for 32x32 images

### Phase 2: Specific Model Adaptations

#### 2.1 Standard ViT Adaptation (ARC_ViT.py)
- Create `CIFAR_ViT.py` based on ARC_ViT.py
- Modify `__init__`:
  - Remove task_token_embed or set num_task_tokens=0
  - Modify patch_embed to accept 3 channels
  - Change positional embedding size calculation
  - Modify head to output num_classes
- Modify `forward`:
  - Remove task token concatenation
  - Add global pooling before norm and head
  - Adjust preprocessing for RGB normalization

#### 2.2 LoopViT Adaptation (ARC_LoopViT.py)
- Create `CIFAR_LoopViT.py` based on ARC_LoopViT.py
- Similar modifications as ViT for input/output
- Evaluate loop mechanism usefulness for CIFAR:
  - Option A: Keep looped structure with shared layers
  - Option B: Modify to have some unique layers per depth
  - Consider whether exit gate is beneficial for CIFAR
- Assess if input injection variant helps with gradient flow

#### 2.3 Enhanced ViT2 Adaptation (ARC_ViT2.py)
- Create `CIFAR_ViT2.py` preserving beneficial innovations:
  - Relative positional bias (may need adjustment for CIFAR scale)
  - RMSNorm and ConvolutionalGLU components
  - Hybrid attention with RoPE + relative bias

### Phase 3: Training Adaptations

#### 3.1 Data Loading
- Create CIFAR-specific data loader (adapt from ARC_loader.py)
- Apply standard CIFAR augmentations (random crop, flip, normalization)

#### 3.2 Loss Function
- Replace ARC's pixel-wise cross-entropy with standard classification loss
- Use `nn.CrossEntropyLoss()` for single-label CIFAR-10/100

#### 3.3 Optimization
- Adjust learning rate schedule (CIFAR typically uses different schedules than ARC)
- Consider warmup + cosine decay or step LR
- Weight decay and other optimizer settings may need tuning

### Phase 4: Validation and Testing

#### 4.1 Baseline Establishment
- Implement standard ViT/Tiny baseline for comparison
- Test adapted models on CIFAR-10 first, then CIFAR-100

#### 4.2 Ablation Studies
- Test importance of LoopViT innovations on CIFAR:
  - Compare standard ViT vs LoopViT vs InputInject variants
  - Evaluate contribution of step embeddings
  - Test exit gate utility (if any)
  - Assess relative positional bias impact (ViT2)

#### 4.3 Scaling Experiments
- Test different model sizes (Ti/Small/Base variants)
- Evaluate computational efficiency vs accuracy tradeoffs

## Risk Mitigation

### Potential Challenges:
1. **Architecture mismatch**: ARC models optimized for reasoning may not suit recognition
   - Mitigation: Start with standard ViT baseline, then add innovations selectively

2. **Scale differences**: 32x32 CIFAR vs variable ARC grids
   - Mitigation: Adjust patch size and positional embeddings appropriately

3. **Output representation**: Pixel-wise vs class-level predictions
   - Mitigation: Fundamental architectural change required in output head

4. **Training dynamics**: Different optimization requirements
   - Mitigation: Use established CIFAR training recipes as starting point

## Success Criteria
- Achieve competitive accuracy with standard ViT baselines on CIFAR-10/100
- Determine which ARC-inspired innovations (if any) transfer beneficially to recognition tasks
- Provide clear comparison between standard approaches and LoopViT variants
